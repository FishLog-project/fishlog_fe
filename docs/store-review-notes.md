# 스토어 검증용 기능·위치정보 안내

2026-09-15 프론트엔드 확인. 관련 이슈: [#33](https://github.com/FishLog-project/fishlog_fe/issues/33).

## 현재 구현에서 확인한 내용

**현재 앱을 ‘위치정보가 단말 안에서만 처리되며 서버로 전송되지 않음’으로 설명할 수 없다.**
주변 시설 조회는 좌표를 FishLog API로 보낸다. 로그인 토큰을 붙이지 않는 것과 좌표를 전송하지 않는 것은 다르다.
DB에 저장하지 않더라도 HTTP 요청의 전송 자체는 발생한다.

| 기능 | 좌표 출처 | 전달 대상·조건 | 근거 |
| --- | --- | --- | --- |
| 지도 초기 표시·현재 위치 버튼 | 권한을 허용한 단말의 현재/마지막 위치 | Kakao 지도 컴포넌트에 카메라 중심·현재 위치 표시값 전달 | `location-store.ts`, `kakao-map.tsx` |
| 음식점·관광지·숙박 조회 | 카테고리를 선택하거나 재조회한 순간의 지도 중심. 지도 중심을 얻지 못하면 단말 위치 | `GET /api/tours/nearby?type=…&lat=…&lng=…`. Authorization 토큰 없음 | `tour-facilities.tsx`, `tour-api.ts`, `client.ts` |
| 낚시터 주소 표시·주소 검색 | 낚시터 목록의 고정 좌표 | Kakao Local `coord2address.json` | `use-spot-view-model.ts`, `use-spot-search.ts`, `kakao-address.ts` |
| 관광 시설 상세의 장소 링크 | 선택한 시설의 좌표·이름 | Kakao Local `search/keyword.json` | `tour-facilities.tsx`, `kakao-place.ts` |

지도 초기 중심은 단말의 현재 위치로 이동할 수 있으므로, **‘지도 중심 좌표라서 사용자 위치와 무관하다’는 설명도 정확하지 않다.**
시설 조회는 카테고리 선택·재조회로 시작하며 지도 이동만으로 매번 요청하지 않는다.
시설 시트를 숨길 때는 기존 결과를 유지한다. 필터 해제·초기화 때 결과를 지운다.

이 저장소에는 위치의 백그라운드 추적 구현이 없다. 위치 권한을 거부해도 기본 지도와 지도 중심 기준 시설 조회를 사용할 수 있다.
단, 지도 SDK가 작동하지 않아 중심을 얻을 수 없고 위치도 허용하지 않은 경우에는 시설 조회 좌표가 없어 안내가 표시된다.

## 검증 담당자 참고사항 초안

> 로그인 화면 하단의 ‘로그인 없이 둘러보기’로 홈과 지도를 확인할 수 있습니다.
> 어종 인증·도감 등록에는 로그인과 서버 통신이 필요합니다.
> 인증 화면의 ‘사진 선택’으로 테스트 이미지를 선택하거나 카메라로 촬영할 수 있습니다.
> 위치 권한은 앱 사용 중 지도 초기 표시와 현재 위치 이동에 사용합니다.
> 주변 시설을 조회하면 조회 기준 좌표가 FishLog 서버로 전송됩니다. 지도 중심을 사용하며, 이 중심은 단말의 현재 위치와 같을 수 있습니다.
> 카메라·위치 권한을 거부했을 때도 사진 선택이나 기본 지도 등 가능한 대안을 제공합니다.

테스트 계정과 검증용 사진은 스토어 콘솔의 비공개 검증 자료에 별도로 넣는다. 계정 비밀번호·토큰·키는 이 문서나 이슈에 기록하지 않는다.

## 제출 전 확인할 경계

- 현재 위치 기능을 유지하는 구현이다. 이미 제출한 ‘미사용/미전송’ 답변은 위의 실제 전송 경로를 전달하여 스토어 담당자와 정정·확인해야 한다. 이 PR은 콘솔의 제출 답변을 자동으로 바꾸지 않는다.
- 백엔드·프록시의 IP/쿼리 로그, 저장·보유기간, 관광 API로 전달하는 범위는 해당 운영 담당자가 확인해야 한다. 프론트만으로 ‘기록되지 않는다’고 확정하지 않는다.
- Kakao SDK 내부 통신·서비스 정책은 별도로 확인해야 한다. 위 표는 프론트에서 SDK/API로 전달하는 입력을 추적한 결과다.
- 사업자 신고 또는 법적 의무 해당 여부를 이 문서로 판정하지 않는다. 팀이 받은 답변의 ‘단말에서만 처리’ 조건과 현재 구현을 동일하게 취급하지 않는다.

## 재확인 방법

1. 위치 권한을 허용하고 지도를 열어 카테고리를 선택한다. 개발용 네트워크 기록에서 `/api/tours/nearby`의 조회 좌표와 지도 중심을 비교한다.
2. 지도를 다른 지역으로 옮기고 재조회하여 새 중심을 사용하는지 확인한다.
3. 권한을 거부한 상태에서는 기본 지도 중심으로 조회되는지 확인한다. 좌표·IP가 들어간 원본 기록은 공개 이슈에 첨부하지 않는다.
4. `node scripts/check-tour-data.cjs`와 `node scripts/check-map-state.cjs`로 좌표 입력·요청 상태·시트 표시의 회귀 검사를 실행한다. 이 검사는 실제 서버 로그나 SDK 통신을 증명하지 않는다.
